# 栈闩工房

机关推箱子纯前端工房。不同种类的箱子触发对应踏板，踏板改变门与地板，记录步数并保存已完成关卡的最佳成绩。

## 本地运行

```bash
npm install
npm run dev
```

类型检查、逻辑断言与生产构建：

```bash
npm run typecheck
npm run verify
npm run build
```

## Docker

```bash
docker compose up --build
```

浏览器打开 http://127.0.0.1:8030

## 联动百叶门（latch-06 / latch-07）

未装百叶的旧五关仍只听原踏板；两个新关引入一只手轮控制一排联动百叶门。

- **一只手轮、一排门**：同组所有叶片转角只由手轮读数 `h ∈ [0°,90°]` 决定。
- **两种肘形**：每只手轮有前肘 / 后肘两条映射 `叶角 = slope × h + offset`。同一读数从两侧进入连杆可以得到不同门形。
- **净空模型**：每片门的净空 = `(1/叶片数)·cos(叶角) − 叶厚`，一排门取最窄的一片。
- **换形点**：两种肘形只有在叶角物理重合的读数才能切换，其余位置硬切等于拆杆，操作会被拒绝。
- **调门预览（盘面规划）**：在 `(读数 × 肘形)` 状态图上 BFS，转动边逐角度扫掠，换形边只在换形点出现。可行时给出"转到几度、何处换形"的完整经过；不可行时给出两种肘形各自的够宽区间和第一处卡转角度。
- **扫掠干涉**：转动过程中任何中间角度碰到人或箱，整段转动即拒绝，不会因为终点够宽就放行。门格自身任何时刻有人/箱都机械干涉；显式守卫格在叶角收小到阈值以下时被探入的叶片扫到。
- **通行只认当前门形**：推箱过门按当前选定货物宽度校验当前肘形的真实净空，另一肘形上够宽的结果不会被借用。
- **操作**：人站到手轮格后，按钮或快捷键 `Q/E` 转 ±5°、`F` 换肘形；货物宽度可在侧栏切换，预览与通行同步按它校验。

`npm run verify` 覆盖：旧关回归、换形点重合校验、跨肘形规划、非换形点拒绝换形、当前门形通行、扫掠碰箱/碰身卡转、窄货与宽货的可达性差异。
